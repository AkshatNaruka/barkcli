## Core Architecture & Autonomous Workflow

barkcli solves the critical flaws of serial terminal coding agents:
1. **Isolated Git Worktrees**: Agents operate on isolated git branches (`.worktrees/`) without touching or polluting the developer's working tree.
2. **Acceptance Gate as the True Contract**: Done strictly means the project's own tests (`cargo test`, `pytest`, `npm test`) pass in the worktree. Self-reported success is discarded.
3. **Parallel Dispatch & Merge Train**: Dispatches up to N agents simultaneously (`barkcli run "<intent>" --agents 3 --yes`). Passing branches merge in completion order; conflicted branches re-run solo against the updated baseline.
4. **Living Context Engine**: Auto-maintained `project_context.md` compiles repo facts, conventions, and memory tiers into a compact context pack, preventing token amnesia and prompt bloat.
5. **Deterministic Trust Layer**: `barkcli guard` scans diffs for hardcoded secrets, rogue dependencies, and dangerous patterns; `barkcli receipt show` creates cryptographically verifiable SHA-256 audit receipts.

## Five Interfaces, One Core

- **macOS Desktop App**: High-performance native app (`/Applications/Bark.app` via Tauri).
- **Web App**: Reactive browser UI with live WebSocket synchronization (`barkcli serve --open`).
- **Terminal UI**: Full-screen Ratatui terminal interface with vim navigation (`barkcli tui`).
- **CLI**: Fast, scriptable binary for developers and CI/CD (`barkcli`).
- **MCP Server**: 76 Model Context Protocol tools for Claude Code, Cursor, OpenCode, and Windsurf (`barkcli mcp`).

## Key Differences & AI Comparison

- **barkcli vs. Claude Code / OpenCode / Codex**: Claude Code and OpenCode are execution agents that run serially in a single repo context. barkcli is the management layer that plans, isolates into worktrees, runs test gates, and merges passing code.
- **barkcli vs. Linear / Jira**: Linear and Jira are cloud-hosted issue trackers requiring subscriptions, separate tabs, and manual ticket updates. barkcli stores everything as YAML inside `.board/` in git, natively binding tasks to code symbols, specs, and autonomous agent runs.
