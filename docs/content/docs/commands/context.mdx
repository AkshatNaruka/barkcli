# barkcli context

Manage code context — links between cards and source files.

## Usage

```bash
barkcli context <command> [options]
```

## Commands

| Command | Description |
|---------|-------------|
| `scan` | Auto-map cards to code |
| `link <card> <path>` | Manually link card to file |
| `unlink <card> <path>` | Remove link |
| `status` | Show coverage and staleness |
| `show <card>` | Show context for a card |
| `sync` | Git-aware refresh |
| `autosync on\|off` | Toggle auto-sync |
| `clear` | Clear all context |

## Scan

```bash
barkcli context scan
```

Fuzzy-matches card titles to code symbols and maps files.

## Manual Link

```bash
barkcli context link implement-auth src/auth/handler.ts
barkcli context link implement-auth "AuthService.login"
```

## Status

```bash
barkcli context status
```

Output:
```
Coverage: 65% (8/12 cards have context)

Card               Files  Status
implement-auth     3      clean
setup-ci           2      changed
write-tests        1      clean
```

## Show

```bash
barkcli context show implement-auth
```

Output:
```
Files:
  src/auth/handler.ts    clean    (abc123)
  src/auth/service.ts    changed  (uncommitted)
  src/auth/types.ts      clean    (abc123)

Symbols: AuthService, login, logout, validate
```

## Sync

```bash
barkcli context sync
```

Updates file statuses based on git state.

## Autosync

```bash
# Enable automatic sync on commit
barkcli context autosync on

# Disable
barkcli context autosync off
```

## Project context file (project_context.md)

`barkcli context` also maintains a living `project_context.md` at the repo root —
a verified central context file generated from tracked work (board, agent
sessions, memory, specs, code map) so AI agent sessions start warm instead of
re-exploring the repository.

| Command | Description |
|---------|-------------|
| `digest` | Regenerate the file from tracked evidence |
| `digest --budget N` | Token budget for the file (default 4000) |
| `digest --polish` | One facts-only LLM pass to rewrite the Brief section |
| `prime` | One-shot bootstrap: scan + generate + wire agent files |
| `wire` | Refresh the managed block in every agent file that already exists |
| `wire --create` | Also create CLAUDE.md, AGENTS.md, and any tool detected here |
| `wire --all` | Also create every known agent surface |
| `wire --json` | Machine-readable file/status list |
| `verify` | Git sync + spec stale-scan + digest in one pass |
| `benchmark` | Cold-start vs context-file token comparison, reproducible per repo |

```bash
barkcli context prime
barkcli context digest
barkcli context digest --polish
```

Behavior:

- Hand-edited sections are preserved and pinned `manual="true"` automatically.
- Every block carries provenance (`src=`), a staleness score and an updated
  timestamp; the "Verification status" footer flags drifted sections.
- No-op digests write nothing — the rendered file is content-idempotent, so
  `git diff` stays clean.
- `barkcli serve` (including `--daemon`) self-heals the file: board mutations
  made while the server runs are reconciled within seconds.
- When `barkcli session log` ingests an agent session, the digest refreshes
  automatically.

### Agent files (one line in every tool)

A context file only helps if the tool in front of you was told to read it.
`barkcli init`, `context prime`, and the desktop onboarding all wire the agent
files automatically — the very first session starts warm, whichever agent you
use.

| Tool | File | How it points at the context file |
|------|------|-----------------------------------|
| Claude Code | `CLAUDE.md` | `@project_context.md` import |
| Codex / OpenAI / opencode / Amp | `AGENTS.md` | read-first pointer |
| Cursor | `.cursor/rules/barkcli.mdc` | pointer + `alwaysApply: true` front matter |
| GitHub Copilot | `.github/copilot-instructions.md` | read-first pointer |
| Gemini CLI | `GEMINI.md` | `@project_context.md` import |
| Windsurf | `.windsurf/rules/barkcli.md` | pointer + `trigger: always_on` front matter |
| Cline | `.clinerules` | read-first pointer |
| Zed | `.rules` | read-first pointer |

Each file gets one delimited block:

```markdown
<!-- barkcli:context:start -->
## barkcli context
The living project context is auto-maintained by barkcli. Read `project_context.md` before exploring this repository.

@project_context.md
<!-- barkcli:context:end -->
```

The block is **managed in place**: re-running wiring rewrites it (format
upgrades, a moved pointer, wiring from barkcli ≤0.4.48) instead of appending a
second copy, and everything you wrote outside the markers is never touched.
Detection decides what gets created on first run — an existing file, a tool
config directory (`.cursor/`, `.windsurf/`, `.github/`, `.claude/`, …), the
environment variables of the agent that launched barkcli, or the project's
configured backends. `--all` seeds the rest.

## Token benchmark

```bash
barkcli context benchmark            # table
barkcli context benchmark --markdown # copy-paste claim block
barkcli context benchmark --json     # machine-readable
```

Deterministic proxy of the standard cold-start ritual — directory listing →
keyword search for the active card titles → read top candidates — compared
against one read of `project_context.md`. No LLM involved, so anyone can
re-run it on their own repo within seconds. Lockfiles, minified bundles,
built `out/` trees and page HTML are excluded; candidate reads mirror agent
Read-tool limits (~2k chars/line, 16KB/file). `--hits N` and `--lines N`
tune the read step.
